# 对话流程详解

本文按一次对话的时间顺序，讲解孩子发出一句话之后，系统怎样做意图审查、怎样决定画画、怎样审查输出，以及耗时是怎样记录的。文中链接指向对应的代码文件。各文件的作用见 [目录说明.md](目录说明.md)；核心代码文件开头都写有本文件在审查链路中所处位置的说明。

## 全景

```
孩子发送（网页）                         第三方系统
  │  useChat.run → POST /api/chat          │  POST /v1/responses（API Key 鉴权，见第 11 节）
  ▼                                        ▼
  ① 校验配置与角色、清洗消息（各入口自己完成）
  ─────────────── 以下为共用的对话主链路 runChat（lib/server/chat.ts） ───────────────
  ② 注入关键词 ──命中──→ 友好拒绝                                   path=injection
  ③ 意图审查 ∥ 主模型生成（同时开始）
       ├─ draw    → 中止生成 → 画画流程（见第 6 节）              path=draw / draw_*
       ├─ unsafe  → 中止生成 → 安全提示话术                       path=unsafe_intent
       ├─ bypass  → 中止生成 → 友好拒绝                           path=refusal
       └─ normal  → 等生成完成
  ④ 输出审查
       ├─ pass     → 下发回答                                    path=answer
       ├─ unsafe   → 安全提示话术                                path=unsafe_output
       ├─ error    → 严格模式下不放行，返回兜底话术              path=guard_error
       └─ homework → 严格引导重写 → 再审 → 下发或固定引导话术     path=rewrite / fallback
  ⑤ 写一行审计记录
  ▼
网页：按 SSE 事件更新消息，正在想 → 守护检查中 / 画画中 → 答案（打字机效果）
第三方：等审查完成后，一次性返回 OpenAI Responses 格式的 JSON
```

两个入口共用同一条主链路，第三方无法绕过任何一道引导或审查。

核心原则是**先审后放**：生成的内容在服务端攒齐、通过审查后才下发。孩子能看到的只有两类内容：通过审查的模型回答，以及代码中预置的固定话术。

## 引导与审查的分工

"引导"是要求主模型守规矩，"审查"是由另一个模型检查结果，两者分层叠加：

| 层 | 作用于 | 作用 | 代码 |
|---|---|---|---|
| 守护硬规则 | 主模型 | 系统提示词最前面，规定只引导不代写，附常见绕法与示范对话 | [rules.ts](../src/lib/server/guard/rules.ts) |
| 角色人设 | 主模型 | 只影响语气，声明不得违背硬规则 | [policy.ts](../src/lib/server/guard/policy.ts) |
| 引导模式 | 主模型 | 命中作业关键词时，本轮追加"只给思路、不给成品" | [policy.ts](../src/lib/server/guard/policy.ts) |
| 守则提醒 | 主模型 | 贴在孩子最新一句话前，对话再长也不会被"遗忘" | [policy.ts](../src/lib/server/guard/policy.ts) |
| 注入拦截 | 输入 | 关键词命中明显的注入话术，直接拒绝 | [intent.ts](../src/lib/server/guard/intent.ts) |
| 意图审查 | 输入 | 审查模型判断孩子想干什么：正常、绕过规则、不安全或想画画 | [intent.ts](../src/lib/server/guard/intent.ts) |
| 输出审查 | 输出 | 审查模型判断回答能否给孩子看：通过、代写或不安全 | [review.ts](../src/lib/server/guard/review.ts) |
| 纠正重写 | 主模型 | 判为代写后按纠正提示重写，重写结果再审一次 | [policy.ts](../src/lib/server/guard/policy.ts) |
| 固定话术 | 输出 | 审查不通过时的兜底，不经过模型 | [policy.ts](../src/lib/server/guard/policy.ts) |

## 1. 孩子发起对话（前端）

孩子在输入框发送后，[ChatView.tsx](../src/components/ChatView.tsx) 调用 `chat.send`，进入 [useChat.ts](../src/lib/useChat.ts)：先把孩子的消息写入会话，再调用 `run`。

`run` 的主要步骤（[useChat.ts](../src/lib/useChat.ts)）：

1. **整理历史**（[useChat.ts](../src/lib/useChat.ts)）：只带 `role` 和 `content`，去掉报错消息。图片地址只保存在前端，不会发给模型。
2. **插入占位回答**（[useChat.ts](../src/lib/useChat.ts)）：状态为 `thinking`，界面显示跳动的三个点和"正在想"。
3. **发起请求**（[useChat.ts](../src/lib/useChat.ts)）：请求体只有 `roleId` 和 `messages`，模型和系统提示词完全由服务端决定。
4. **逐帧解析 SSE**（[useChat.ts](../src/lib/useChat.ts)），按事件更新消息，见第 8 节。

## 2. 服务端入口：校验与清洗

网页入口在 [route.ts](../src/app/api/chat/route.ts)，清洗和检查完成后调用对话主链路 `runChat`。第 3～9 节讲的都是 `runChat` 内部的步骤，第三方入口的差异见第 11 节。

- **消息清洗**（[route.ts](../src/app/api/chat/route.ts)）：
  - 只保留 `user`/`assistant` 两种角色，单条截到 500 字，最多保留最近 20 条。
  - 去掉开头的助手消息，并要求最后一条必须是孩子的消息。
  - 客户端如果伪造 `system` 消息或 `model` 字段，会在这一步被丢弃。
- **配置检查**（[route.ts](../src/app/api/chat/route.ts)）：对话模型或审查模型没配置时返回 503"学伴还没准备好"；角色不存在或消息不合法时返回 400。
- **准备工作**：
  - [chat.ts](../src/lib/server/chat.ts)：取出最后一句话，用作业关键词判断本轮要不要进入**引导模式**，正则在 [intent.ts](../src/lib/server/guard/intent.ts)。
  - [chat.ts](../src/lib/server/chat.ts)：开始审计计时，见第 9 节。
- **建立 SSE 流**（[route.ts](../src/app/api/chat/route.ts)）：`send` 用来下发事件；每 15 秒发一次 `: ping` 心跳，防止画画这类长时间等待被代理断开连接。前端会忽略心跳帧。

## 3. 第一道关：注入关键词

[chat.ts](../src/lib/server/chat.ts)：孩子的话如果命中"忽略规则""开发者模式""越狱"等注入话术（正则在 [intent.ts](../src/lib/server/guard/intent.ts)），直接回一句随机的友好拒绝（[policy.ts](../src/lib/server/guard/policy.ts)），**不调用任何模型**，审计路径记为 `injection`。

## 4. 意图审查与主模型生成（同时进行）

这是整个流程里最关键的设计：**意图审查和主模型生成同时开始**，正常提问的等待时间不会因为多了一次审查而变长。

### 4.1 主模型开始生成

[chat.ts](../src/lib/server/chat.ts)

- **系统提示词**（[policy.ts](../src/lib/server/guard/policy.ts)），依次拼接三部分：
  1. 守护硬规则（可在控制台修改，默认值在 [rules.ts](../src/lib/server/guard/rules.ts)，内含常见绕法和示范对话）
  2. 角色人设
  3. 命中作业关键词时追加的引导模式指令（[policy.ts](../src/lib/server/guard/policy.ts)）
- **守则提醒**（[policy.ts](../src/lib/server/guard/policy.ts)）：只在发给模型的那份副本里，给最后一句话前面加上"【学伴守则：…】孩子说："。这样聊得再久规则也不容易失效，孩子话里的"忽略规则"也会被明确当作孩子说的话。
- **可中止**：生成挂在 `draftCtrl` 上（[chat.ts](../src/lib/server/chat.ts)），意图审查一旦判为非正常，就能立刻中止，不浪费 token。
- 模型调用走 [llm.ts](../src/lib/server/llm.ts)：Responses 协议带上 `store: false`，不让厂商留存孩子的对话。

### 4.2 意图审查

[chat.ts](../src/lib/server/chat.ts) → [intent.ts](../src/lib/server/guard/intent.ts) → [judge.ts](../src/lib/server/guard/judge.ts)

- **输入**：最近 5 条消息，转成"孩子：… / 助手：…"格式（[judge.ts](../src/lib/server/guard/judge.ts)）。看多轮上下文，是为了识别"被引导后仍然反复索要成品"这类情况。
- **提示词**：分为 `bypass`（绕过规则）、`unsafe`（不安全）、`normal`。启用绘画时再加一个 `draw`（[intent.ts](../src/lib/server/guard/intent.ts)），并明确说明"交作业用的画不算 draw"。
- **调用审查模型**（[judge.ts](../src/lib/server/guard/judge.ts)）：最多输出 10 个 token，6 秒超时，只要求输出一个单词。
- **解析结论**（[judge.ts](../src/lib/server/guard/judge.ts)）：按词表顺序查找第一个出现的词，**词表顺序就是优先级**：`unsafe` > `bypass` > `draw` > `normal`（[intent.ts](../src/lib/server/guard/intent.ts)）。
- **出错放行**：超时、调用失败或输出解析不出来时，返回 `normal`（[intent.ts](../src/lib/server/guard/intent.ts)），因为后面还有输出审查这道硬关卡。

### 4.3 分流

[chat.ts](../src/lib/server/chat.ts)

| 意图 | 处理 | 审计路径 |
|---|---|---|
| `draw` | 中止生成，进入画画流程 | 由画画流程返回 |
| `unsafe` | 中止生成，下发安全提示话术（[policy.ts](../src/lib/server/guard/policy.ts)） | `unsafe_intent` |
| `bypass` | 中止生成，下发友好拒绝 | `refusal` |
| `normal` | 继续等待生成结果，进入第 7 节 | — |

## 5. 交作业用的画为什么不出图

这类请求要分两层看：
- **意图审查**：提示词规定手抄报、美术作业等不算 `draw`（[intent.ts](../src/lib/server/guard/intent.ts)），所以按 `normal` 走文字回答。
- **作业关键词**：正则里包含"手抄报""美术作业"（[intent.ts](../src/lib/server/guard/intent.ts)），本轮会追加引导模式。主模型只会给出构图和配色思路，然后照常经过输出审查。

## 6. 画画流程

入口：[chat.ts](../src/lib/server/chat.ts) → [draw/index.ts](../src/lib/server/draw/index.ts)

1. **选模板**：读取绘画配置和当前模板（[config.ts](../src/lib/server/config.ts)），模板 id 写进审计记录（[index.ts](../src/lib/server/draw/index.ts)）。
2. **繁忙检查**（[index.ts](../src/lib/server/draw/index.ts)）：查询 ComfyUI 的 `/queue`，等待数加运行数达到上限就回"小画家正忙"，路径记为 `draw_busy`。ComfyUI 连不上时记为 `draw_failed`。
3. **改写提示词**（[index.ts](../src/lib/server/draw/index.ts) → [prompt.ts](../src/lib/server/draw/prompt.ts)）：
   - 先推送 `drawing {stage:'prompt'}`，界面显示"正在构思画面"。
   - 审查模型读取最近 5 条消息，输出 `{"reply","prompt"}` 两个字段（提示词见 [prompt.ts](../src/lib/server/draw/prompt.ts)）：
     - `prompt` 用模板指定的语言：Z-Image 用中文，H3 用英文。
     - `reply` 是给孩子的一句话，比如"好呀，我来画一只在月亮上钓鱼的小猫"。
   - 最多输出 400 个 token，20 秒超时。解析失败时回"这次没画出来"。
4. **提示词安全复核**（[index.ts](../src/lib/server/draw/index.ts) → [prompt.ts](../src/lib/server/draw/prompt.ts)）：
   - 再用审查模型判一次 `pass` 或 `unsafe`（提示词见 [prompt.ts](../src/lib/server/draw/prompt.ts)）。
   - 判为不安全时回安全提示话术，路径 `draw_unsafe`。
   - 审查故障时按严格模式不放行，返回兜底话术，路径 `guard_error`。
5. **提交 ComfyUI 并等待**（[index.ts](../src/lib/server/draw/index.ts) → [comfy.ts](../src/lib/server/draw/comfy.ts)）：
   - **准备工作流**（[comfy.ts](../src/lib/server/draw/comfy.ts)）：复制模板工作流，把提示词加上风格后缀写入提示词节点，种子节点换成随机数。
   - **提交**（[comfy.ts](../src/lib/server/draw/comfy.ts)）：`POST /prompt` 拿到 `prompt_id`。超时信号和孩子的中止信号合并在一起。
   - **每秒轮询**（[comfy.ts](../src/lib/server/draw/comfy.ts)）：
     - 先查 `/history/{id}`，有结果就去下载。
     - 还没完成就查 `/queue`，算出"前面还有几幅"或"正在渲染"，状态变化时才推送一次 `drawing` 事件（[comfy.ts](../src/lib/server/draw/comfy.ts)），前端随之显示排队位置和已用秒数。
   - **下载保存**（[comfy.ts](../src/lib/server/draw/comfy.ts)）：
     - 通过 `/view` 下载第一张图，用随机文件名存进 `data/images/`。
     - 同时返回三段耗时：排队 `drawQueue`、渲染 `drawRender`、下载 `drawFetch`。
   - **中止或超时**（[comfy.ts](../src/lib/server/draw/comfy.ts)）：任务还在排队就从队列删除；正在渲染时，**只有确认是自己的任务**才调用 `/interrupt`，不会打断别的孩子的任务。
6. **下发结果**（[index.ts](../src/lib/server/draw/index.ts)）：下发 `answer {text: reply, image: '/api/images/<文件名>'}`，路径 `draw`。图片由 [images/[name]/route.ts](../src/app/api/images/%5Bname%5D/route.ts) 提供；文件名必须是 `uuid.png/jpg/webp` 格式（[route.ts](../src/app/api/images/%5Bname%5D/route.ts)），防止被用来读取任意文件。

## 7. 输出审查

只有意图为 `normal` 的请求才会走到这里：[chat.ts](../src/lib/server/chat.ts)

1. **等待生成完成**（[chat.ts](../src/lib/server/chat.ts)）：模型返回空内容时视为出错。
2. **通知前端**（[chat.ts](../src/lib/server/chat.ts)）：发送 `reviewing` 事件，这个事件不含任何回答内容，只是让界面从"正在想"切换到"守护检查中"。
3. **调用审查**（[chat.ts](../src/lib/server/chat.ts) → [review.ts](../src/lib/server/guard/review.ts)）：
   - 输入是最近 3 条消息加【待审回答】。
   - 提示词（[review.ts](../src/lib/server/guard/review.ts)）区分三种结论：
     - `homework`：替孩子写了作品或给了作业答案
     - `unsafe`：内容不适合儿童
     - `pass`：知识科普、启发式提问、与作业无关的举例、娱乐性小故事等
   - 要求"拿不准时按违规处理"。
   - **严格模式**（[review.ts](../src/lib/server/guard/review.ts)）：审查调用失败或输出解析不出来时，`GUARD_STRICT=true`（默认）返回 `error`，不放行模型生成的内容；设为 `false` 时放行。
4. **按结论处理**（[chat.ts](../src/lib/server/chat.ts)）：
   - `pass`：原样下发。
   - `unsafe`：换成安全提示话术。
   - `error`：以正常回答的形式返回兜底话术（[policy.ts](../src/lib/server/guard/policy.ts) 中的 `GUARD_DOWN`），不向客户端暴露故障。
   - `homework`：
     1. 用"引导模式 + 纠正提示"（[policy.ts](../src/lib/server/guard/policy.ts)）让主模型重新生成（[chat.ts](../src/lib/server/chat.ts)）。
     2. 对重新生成的结果**再审一次**（[chat.ts](../src/lib/server/chat.ts)）。
     3. 通过就下发，路径 `rewrite`；不通过就用固定引导话术（[policy.ts](../src/lib/server/guard/policy.ts)），路径 `fallback`。

## 8. 前端接收与展示

SSE 事件在 [useChat.ts](../src/lib/useChat.ts) 中处理：

| 事件 | 数据 | 前端动作 | 展示（[Message.tsx](../src/components/Message.tsx)） |
|---|---|---|---|
| `reviewing` | `{}` | 状态改为 `reviewing` | 三个点 + 盾牌图标"守护检查中"（[Message.tsx](../src/components/Message.tsx)） |
| `drawing` | `{stage, ahead?}` | 状态改为 `drawing`，记录阶段 | 画布占位动效，显示阶段文字和计秒（[Message.tsx](../src/components/Message.tsx)） |
| `answer` | `{text, image?, guided?}` | 写入内容和图片；`guided` 标为引导 | 打字机效果，最多约 0.9 秒；有图片时显示图片和"保存图片"按钮（[Message.tsx](../src/components/Message.tsx)） |
| `error` | `{message}` | 状态改为 `error` | 虚线气泡，可以重新回答 |

- 流结束时，如果消息还停在等待状态（连接意外断开），标记为"回答中断了"（[useChat.ts](../src/lib/useChat.ts)）。
- 页面刷新时，所有还没完成的消息都会改成"被打断"（[sessions.ts](../src/store/sessions.ts)），未经审查的状态不会残留。

## 9. 审计记录（贯穿全程）

实现在 [audit.ts](../src/lib/server/audit.ts)。

- **开始**：[chat.ts](../src/lib/server/chat.ts) 创建记录，写入角色、对话模型、审查模型、输入字数，以及是否命中引导模式。
- **计时**（[audit.ts](../src/lib/server/audit.ts)）：
  - `audit.time(阶段, Promise)` 从调用的那一刻开始计时，到 Promise 成功结束为止。
  - 意图审查和生成是并行的，各自独立计时。
  - **只有成功完成的阶段才会记录**，被意图审查中止的那次生成不会计入。
  - 涉及的位置：
    - [chat.ts](../src/lib/server/chat.ts)：生成
    - [chat.ts](../src/lib/server/chat.ts)：意图审查
    - [chat.ts](../src/lib/server/chat.ts)：输出审查
    - [chat.ts](../src/lib/server/chat.ts)：重新生成与二次审查
    - [index.ts](../src/lib/server/draw/index.ts)：画画提示词的改写与复核
    - [index.ts](../src/lib/server/draw/index.ts)：ComfyUI 的排队、渲染、下载
- **补充字段**：意图、审查结论、输出字数、画画模板等，通过 `audit.set` 写入（[audit.ts](../src/lib/server/audit.ts)）。
- **结束**：[chat.ts](../src/lib/server/chat.ts) 在 `finally` 中调用 `finish`，不管走哪条路径都只写一次；孩子中止时路径记为 `aborted`。
  - `finish`（[audit.ts](../src/lib/server/audit.ts)）把完整记录追加到 `data/logs/audit-YYYY-MM.jsonl`，并在服务日志中打一行中文结果摘要（info 级别，见第 12 节）。写入失败只打日志，不影响对话。
- **不记录**对话原文和图片内容。
- 控制台"审计"页读取这些文件，统计 P50 和 P95；也可以一键清除，清除需要二次确认，删除后不可恢复（[audit/route.ts](../src/app/api/admin/audit/route.ts)）。

## 10. 停止、超时与异常

| 情况 | 处理 |
|---|---|
| 孩子点"停止" | 前端中止请求（[useChat.ts](../src/lib/useChat.ts)）。服务端的 `req.signal` 随之中止，并传到所有模型调用和 ComfyUI 轮询；ComfyUI 任务会被删除或中断。审计路径为 `aborted` |
| 意图审查超时（6 秒） | 当作 `normal`，继续走输出审查 |
| 输出审查超时（6 秒） | 严格模式下不放行，返回兜底话术，路径 `guard_error` |
| 画画超时（默认 180 秒，可在控制台修改） | 取消 ComfyUI 任务，回"这次没画出来"，路径 `draw_failed` |
| 主模型报错或返回空内容 | 回"我刚刚走神了"（[chat.ts](../src/lib/server/chat.ts)），路径 `error` |

## 11. 第三方入口：/v1/responses

第三方系统用控制台"API 接入"中创建的 Key 调用，接口兼容 OpenAI Responses，可以直接用 OpenAI SDK 调用（`baseURL` 设为 `http://<host>/v1`）。代码在 [v1/responses/route.ts](../src/app/v1/responses/route.ts)，Key 的生成与校验在 [apikeys.ts](../src/lib/server/apikeys.ts)。给第三方的接入说明见 [第三方接入.md](第三方接入.md)。

1. **鉴权**：校验 `Authorization: Bearer <key>`。服务端只保存 Key 的 sha256 哈希，用定时比较防止时序攻击；日志中 Key 只显示首尾。
2. **model 即角色**：可用的值见 `GET /v1/models`。
3. **一问一答**：
   - 只取 `input` 中**最后一条用户消息**的文字，截到 500 字，不带任何上下文。所以第三方没法伪造历史回复来绕过审查。
   - `instructions`、`temperature` 等字段一律忽略，系统提示词只由服务端决定。
4. **走同一条主链路**：调用 `runChat`，第 3～9 节的注入拦截、意图审查、画画、输出审查和审计全部照常执行。审计记录的 `client` 字段是 Key 的名称，网页端是 `web`。
5. **返回结果**：
   - **非流式**：等审查完成后返回 Responses 对象，回答在 `output[0].content[0].text`，SDK 中可以直接用 `response.output_text`。
   - **流式**（`stream: true`）：仍然先审后放。请求一到就推送 `response.created`，审查和画画期间每 15 秒发一次心跳；审查通过后，把最终文本分段推送为 `response.output_text.delta`，最后推送 `response.completed`。未经审查的内容不会出现在流里，首字等待时间与非流式相同。
   - **扩展字段 `metadata`**（值均为字符串）：
     - `path`：审计路径。
     - `guided`：`"true"` 表示这条回答被系统替换或拒绝，对应 `refusal`、`injection`、`rewrite`、`fallback`、`guard_error`。孩子第一次要作文时，主模型在引导模式下自己给出引导，审查通过，记为 `answer`，此时 `guided` 为 `"false"`。
     - `image_url`：画画时图片的绝对地址。
   - **审查故障**：不返回错误，而是以正常回答返回兜底话术，`path=guard_error`、`guided="true"`。客户端照常展示，不会看到故障信息。
   - **出错**：主模型出错时返回 502，格式为 OpenAI 错误。流式下改为推送 `error` 事件，SDK 会抛出 `APIError`。

## 12. 日志

实现在 [log.ts](../src/lib/server/log.ts)，各阶段代码值的中文含义统一在 [labels.ts](../src/lib/labels.ts) 中维护，控制台"审计"页也使用这份对照。

- **级别**：`debug < info < warn < error`，默认 `info`。可以在控制台"审计"页在线切换，立即生效；也可以通过环境变量 `LOG_LEVEL` 设置默认值，控制台的设置优先。
- **请求编号**：入口为每个请求分配一个 8 位编号，之后这个请求的每一行日志都带上它。用 `grep` 搜编号，就能筛出一次请求的完整过程。
- **格式**：单行中文文本，只打印关键信息，不输出 JSON 结构体。代码值都附带中文含义，例如 `path=refusal（绕过拒绝）`、`intent=bypass（绕过规则）`、`verdict=homework（代写）`。
- **各级别打印的内容**：

| 级别 | 内容 |
|---|---|
| debug | 每个阶段一行：入参审批、开始（问题前 40 字）、注入检查、引导模式、意图分析、审查模型原始输出、生成回答、输出审查、改写与二次审查、画画各步骤 |
| info | 每次对话结束一行结果摘要：处理路径、意图、审查结论、调用方、角色、输出字数、总耗时及各阶段耗时 |
| warn | 降级与异常：请求被拒绝、审查模型调用失败或输出无法识别、画画失败 |
| error | 错误：读取配置失败、主模型出错等 |

debug 级别下，一次被判为代写、改写后通过的对话大致如下：

## 附：一次请求会调用几次模型

| 路径 | 审查模型 | 主模型 | ComfyUI |
|---|---|---|---|
| 注入拦截 | 0 | 0 | 0 |
| 绕过拒绝 / 不安全提问 | 1（意图） | 1（被中止） | 0 |
| 正常回答 | 2（意图、输出） | 1 | 0 |
| 代写后重写 | 3（意图、输出、二次） | 2 | 0 |
| 画画 | 3（意图、改写提示词、复核） | 1（被中止） | 1 个任务 |

审查模型每次只输出一个单词（改写提示词这一步除外），所以务必选用快速、非推理的模型，并按需通过 `GUARD_EXTRA_BODY` 关闭思考。
