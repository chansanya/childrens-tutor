# 对话流程详解

本文按一次对话的时间顺序，讲解孩子发出一句话之后，系统怎样做意图审查、怎样决定画画、怎样审查输出，以及耗时是怎样记录的。文中链接指向具体代码行，行号对应编写本文时的代码，代码改动后可能有偏移。各文件的作用见 [目录说明.md](目录说明.md)；核心代码文件开头都写有本文件在审查链路中所处位置的说明。

## 全景

```
孩子发送
  │  前端 useChat.run：插入占位消息，POST /api/chat
  ▼
/api/chat（服务端）
  ① 校验配置与角色、清洗消息
  ② 注入关键词 ──命中──→ 友好拒绝                                   path=injection
  ③ 意图审查 ∥ 主模型生成（同时开始）
       ├─ draw    → 中止生成 → 画画流程（见第 6 节）              path=draw / draw_*
       ├─ unsafe  → 中止生成 → 安全提示话术                       path=unsafe_intent
       ├─ bypass  → 中止生成 → 友好拒绝                           path=refusal
       └─ normal  → 等生成完成
  ④ 输出审查
       ├─ pass     → 下发回答                                    path=answer
       ├─ unsafe   → 安全提示话术                                path=unsafe_output
       ├─ error    → 严格模式下不放行                            path=guard_error
       └─ homework → 严格引导重写 → 再审 → 下发或固定引导话术     path=rewrite / fallback
  ⑤ 写一行审计记录
  ▼
前端按 SSE 事件更新消息：正在想 → 守护检查中 / 画画中 → 答案（打字机效果）
```

核心原则是**先审后放**：生成的内容在服务端攒齐、通过审查后才下发。孩子能看到的只有两类内容：通过审查的模型回答，以及代码中预置的固定话术。

## 引导与审查的分工

"引导"是要求主模型守规矩，"审查"是由另一个模型检查结果，两者分层叠加：

| 层 | 作用于 | 作用 | 代码 |
|---|---|---|---|
| 守护硬规则 | 主模型 | 系统提示词最前面，规定只引导不代写，附常见绕法与示范对话 | [rules.ts](../src/lib/server/guard/rules.ts) |
| 角色人设 | 主模型 | 只影响语气，声明不得违背硬规则 | [policy.ts:47-50](../src/lib/server/guard/policy.ts#L47-L50) |
| 引导模式 | 主模型 | 命中作业关键词时，本轮追加"只给思路、不给成品" | [policy.ts:18](../src/lib/server/guard/policy.ts#L18) |
| 守则提醒 | 主模型 | 贴在孩子最新一句话前，对话再长也不会被"遗忘" | [policy.ts:54-55](../src/lib/server/guard/policy.ts#L54-L55) |
| 注入拦截 | 输入 | 关键词命中明显的注入话术，直接拒绝 | [intent.ts:22](../src/lib/server/guard/intent.ts#L22) |
| 意图审查 | 输入 | 审查模型判断孩子想干什么：正常、绕过规则、不安全或想画画 | [intent.ts:41-43](../src/lib/server/guard/intent.ts#L41-L43) |
| 输出审查 | 输出 | 审查模型判断回答能否给孩子看：通过、代写或不安全 | [review.ts:29-31](../src/lib/server/guard/review.ts#L29-L31) |
| 纠正重写 | 主模型 | 判为代写后按纠正提示重写，重写结果再审一次 | [policy.ts:24](../src/lib/server/guard/policy.ts#L24) |
| 固定话术 | 输出 | 审查不通过时的兜底，不经过模型 | [policy.ts:27-44](../src/lib/server/guard/policy.ts#L27-L44) |

## 1. 孩子发起对话（前端）

孩子在输入框发送后，[ChatView.tsx:82](../src/components/ChatView.tsx#L82) 调用 `chat.send`，进入 [useChat.ts:69-75](../src/lib/useChat.ts#L69-L75)：先把孩子的消息写入会话，再调用 `run`。

`run` 的主要步骤（[useChat.ts:14-67](../src/lib/useChat.ts#L14-L67)）：

1. **整理历史**（[第 18 行](../src/lib/useChat.ts#L18)）：只带 `role` 和 `content`，去掉报错消息。图片地址只保存在前端，不会发给模型。
2. **插入占位回答**（[第 21 行](../src/lib/useChat.ts#L21)）：状态为 `thinking`，界面显示跳动的三个点和"正在想"。
3. **发起请求**（[第 27-32 行](../src/lib/useChat.ts#L27-L32)）：请求体只有 `roleId` 和 `messages`，模型和系统提示词完全由服务端决定。
4. **逐帧解析 SSE**（[第 35-57 行](../src/lib/useChat.ts#L35-L57)），按事件更新消息，见第 8 节。

## 2. 服务端入口：校验与清洗

入口在 [route.ts:41](../src/app/api/chat/route.ts#L41)。

- **消息清洗**（[route.ts:31-39](../src/app/api/chat/route.ts#L31-L39)）：
  - 只保留 `user`/`assistant` 两种角色，单条截到 500 字，最多保留最近 20 条。
  - 去掉开头的助手消息，并要求最后一条必须是孩子的消息。
  - 客户端如果伪造 `system` 消息或 `model` 字段，会在这一步被丢弃。
- **配置检查**（[route.ts:46-56](../src/app/api/chat/route.ts#L46-L56)）：对话模型或审查模型没配置时返回 503"学伴还没准备好"；角色不存在或消息不合法时返回 400。
- **准备工作**：
  - [route.ts:60-62](../src/app/api/chat/route.ts#L60-L62)：取出最后一句话，用作业关键词判断本轮要不要进入**引导模式**，正则在 [intent.ts:18-19](../src/lib/server/guard/intent.ts#L18-L19)。
  - [route.ts:63](../src/app/api/chat/route.ts#L63)：开始审计计时，见第 9 节。
- **建立 SSE 流**（[route.ts:67-73](../src/app/api/chat/route.ts#L67-L73)）：`send` 用来下发事件；每 15 秒发一次 `: ping` 心跳，防止画画这类长时间等待被代理断开连接。前端会忽略心跳帧。

## 3. 第一道关：注入关键词

[route.ts:77-80](../src/app/api/chat/route.ts#L77-L80)：孩子的话如果命中"忽略规则""开发者模式""越狱"等注入话术（正则在 [intent.ts:22](../src/lib/server/guard/intent.ts#L22)），直接回一句随机的友好拒绝（[policy.ts:38-44](../src/lib/server/guard/policy.ts#L38-L44)），**不调用任何模型**，审计路径记为 `injection`。

## 4. 意图审查与主模型生成（同时进行）

这是整个流程里最关键的设计：**意图审查和主模型生成同时开始**，正常提问的等待时间不会因为多了一次审查而变长。

### 4.1 主模型开始生成

[route.ts:83-90](../src/app/api/chat/route.ts#L83-L90)

- **系统提示词**（[policy.ts:47-50](../src/lib/server/guard/policy.ts#L47-L50)），依次拼接三部分：
  1. 守护硬规则（可在控制台修改，默认值在 [rules.ts](../src/lib/server/guard/rules.ts)，内含常见绕法和示范对话）
  2. 角色人设
  3. 命中作业关键词时追加的引导模式指令（[policy.ts:18](../src/lib/server/guard/policy.ts#L18)）
- **守则提醒**（[policy.ts:54-55](../src/lib/server/guard/policy.ts#L54-L55)）：只在发给模型的那份副本里，给最后一句话前面加上"【学伴守则：…】孩子说："。这样聊得再久规则也不容易失效，孩子话里的"忽略规则"也会被明确当作孩子说的话。
- **可中止**：生成挂在 `draftCtrl` 上（[第 88 行](../src/app/api/chat/route.ts#L88)），意图审查一旦判为非正常，就能立刻中止，不浪费 token。
- 模型调用走 [llm.ts:38-58](../src/lib/server/llm.ts#L38-L58)：Responses 协议带上 `store: false`，不让厂商留存孩子的对话。

### 4.2 意图审查

[route.ts:93](../src/app/api/chat/route.ts#L93) → [intent.ts:41-43](../src/lib/server/guard/intent.ts#L41-L43) → [judge.ts:14-33](../src/lib/server/guard/judge.ts#L14-L33)

- **输入**：最近 5 条消息，转成"孩子：… / 助手：…"格式（[judge.ts:36-37](../src/lib/server/guard/judge.ts#L36-L37)）。看多轮上下文，是为了识别"被引导后仍然反复索要成品"这类情况。
- **提示词**（[intent.ts:29-33](../src/lib/server/guard/intent.ts#L29-L33)）：分为 `bypass`（绕过规则）、`unsafe`（不安全）、`normal`。启用绘画时再加一个 `draw`（[intent.ts:25](../src/lib/server/guard/intent.ts#L25)），并明确说明"交作业用的画不算 draw"。
- **调用审查模型**（[judge.ts:18-24](../src/lib/server/guard/judge.ts#L18-L24)）：最多输出 10 个 token，6 秒超时，只要求输出一个单词。
- **解析结论**（[judge.ts:25](../src/lib/server/guard/judge.ts#L25)）：按词表顺序查找第一个出现的词，**词表顺序就是优先级**：`unsafe` > `bypass` > `draw` > `normal`（[intent.ts:42](../src/lib/server/guard/intent.ts#L42)）。
- **出错放行**：超时、调用失败或输出解析不出来时，返回 `normal`（[intent.ts:43](../src/lib/server/guard/intent.ts#L43)），因为后面还有输出审查这道硬关卡。

### 4.3 分流

[route.ts:93-106](../src/app/api/chat/route.ts#L93-L106)

| 意图 | 处理 | 审计路径 |
|---|---|---|
| `draw` | 中止生成，进入画画流程 | 由画画流程返回 |
| `unsafe` | 中止生成，下发安全提示话术（[policy.ts:27-28](../src/lib/server/guard/policy.ts#L27-L28)） | `unsafe_intent` |
| `bypass` | 中止生成，下发友好拒绝 | `refusal` |
| `normal` | 继续等待生成结果，进入第 7 节 | — |

## 5. 交作业用的画为什么不出图

这类请求要分两层看：
- **意图审查**：提示词规定手抄报、美术作业等不算 `draw`（[intent.ts:25](../src/lib/server/guard/intent.ts#L25)），所以按 `normal` 走文字回答。
- **作业关键词**：正则里包含"手抄报""美术作业"（[intent.ts:18-19](../src/lib/server/guard/intent.ts#L18-L19)），本轮会追加引导模式。主模型只会给出构图和配色思路，然后照常经过输出审查。

## 6. 画画流程

入口：[route.ts:98-101](../src/app/api/chat/route.ts#L98-L101) → [draw/index.ts:25-70](../src/lib/server/draw/index.ts#L25-L70)

1. **选模板**（[index.ts:26-27](../src/lib/server/draw/index.ts#L26-L27)）：读取绘画配置和当前模板（[config.ts:67](../src/lib/server/config.ts#L67)），模板 id 写进审计记录（[第 37 行](../src/lib/server/draw/index.ts#L37)）。
2. **繁忙检查**（[index.ts:40-45](../src/lib/server/draw/index.ts#L40-L45)）：查询 ComfyUI 的 `/queue`，等待数加运行数达到上限就回"小画家正忙"，路径记为 `draw_busy`。ComfyUI 连不上时记为 `draw_failed`。
3. **改写提示词**（[index.ts:48-50](../src/lib/server/draw/index.ts#L48-L50) → [prompt.ts:26-42](../src/lib/server/draw/prompt.ts#L26-L42)）：
   - 先推送 `drawing {stage:'prompt'}`，界面显示"正在构思画面"。
   - 审查模型读取最近 5 条消息，输出 `{"reply","prompt"}` 两个字段（提示词见 [prompt.ts:17-20](../src/lib/server/draw/prompt.ts#L17-L20)）：
     - `prompt` 用模板指定的语言：Z-Image 用中文，H3 用英文。
     - `reply` 是给孩子的一句话，比如"好呀，我来画一只在月亮上钓鱼的小猫"。
   - 最多输出 400 个 token，20 秒超时。解析失败时回"这次没画出来"。
4. **提示词安全复核**（[index.ts:53-58](../src/lib/server/draw/index.ts#L53-L58) → [prompt.ts:45-46](../src/lib/server/draw/prompt.ts#L45-L46)）：
   - 再用审查模型判一次 `pass` 或 `unsafe`（提示词见 [prompt.ts:22-23](../src/lib/server/draw/prompt.ts#L22-L23)）。
   - 判为不安全时回安全提示话术，路径 `draw_unsafe`。
   - 审查故障时按严格模式不放行，路径 `guard_error`。
5. **提交 ComfyUI 并等待**（[index.ts:61-62](../src/lib/server/draw/index.ts#L61-L62) → [comfy.ts:72-127](../src/lib/server/draw/comfy.ts#L72-L127)）：
   - **准备工作流**（[comfy.ts:74-76](../src/lib/server/draw/comfy.ts#L74-L76)）：复制模板工作流，把提示词加上风格后缀写入提示词节点，种子节点换成随机数。
   - **提交**（[comfy.ts:79-80](../src/lib/server/draw/comfy.ts#L79-L80)）：`POST /prompt` 拿到 `prompt_id`。超时信号和孩子的中止信号合并在一起。
   - **每秒轮询**（[comfy.ts:87-121](../src/lib/server/draw/comfy.ts#L87-L121)）：
     - 先查 `/history/{id}`，有结果就去下载。
     - 还没完成就查 `/queue`，算出"前面还有几幅"或"正在渲染"（[第 105-113 行](../src/lib/server/draw/comfy.ts#L105-L113)），状态变化时才推送一次 `drawing` 事件（[第 115-119 行](../src/lib/server/draw/comfy.ts#L115-L119)），前端随之显示排队位置和已用秒数。
   - **下载保存**（[comfy.ts:89-101](../src/lib/server/draw/comfy.ts#L89-L101)）：
     - 通过 `/view` 下载第一张图，用随机文件名存进 `data/images/`。
     - 同时返回三段耗时：排队 `drawQueue`、渲染 `drawRender`、下载 `drawFetch`。
   - **中止或超时**（[comfy.ts:122-126](../src/lib/server/draw/comfy.ts#L122-L126) → [comfy.ts:64-69](../src/lib/server/draw/comfy.ts#L64-L69)）：任务还在排队就从队列删除；正在渲染时，**只有确认是自己的任务**才调用 `/interrupt`，不会打断别的孩子的任务。
6. **下发结果**（[index.ts:63-66](../src/lib/server/draw/index.ts#L63-L66)）：下发 `answer {text: reply, image: '/api/images/<文件名>'}`，路径 `draw`。图片由 [images/[name]/route.ts:12](../src/app/api/images/%5Bname%5D/route.ts#L12) 提供；文件名必须是 `uuid.png/jpg/webp` 格式（[第 9 行](../src/app/api/images/%5Bname%5D/route.ts#L9)），防止被用来读取任意文件。

## 7. 输出审查

只有意图为 `normal` 的请求才会走到这里：[route.ts:109-134](../src/app/api/chat/route.ts#L109-L134)

1. **等待生成完成**（[第 109-110 行](../src/app/api/chat/route.ts#L109-L110)）：模型返回空内容时视为出错。
2. **通知前端**（[第 111 行](../src/app/api/chat/route.ts#L111)）：发送 `reviewing` 事件，这个事件不含任何回答内容，只是让界面从"正在想"切换到"守护检查中"。
3. **调用审查**（[第 112 行](../src/app/api/chat/route.ts#L112) → [review.ts:29-31](../src/lib/server/guard/review.ts#L29-L31)）：
   - 输入是最近 3 条消息加【待审回答】。
   - 提示词（[review.ts:21-25](../src/lib/server/guard/review.ts#L21-L25)）区分三种结论：
     - `homework`：替孩子写了作品或给了作业答案
     - `unsafe`：内容不适合儿童
     - `pass`：知识科普、启发式提问、与作业无关的举例、娱乐性小故事等
   - 要求"拿不准时按违规处理"。
   - **严格模式**（[review.ts:31](../src/lib/server/guard/review.ts#L31)）：审查调用失败或输出解析不出来时，`GUARD_STRICT=true`（默认）返回 `error`，不放行；设为 `false` 时放行。
4. **按结论处理**（[第 115-134 行](../src/app/api/chat/route.ts#L115-L134)）：
   - `pass`：原样下发。
   - `unsafe`：换成安全提示话术。
   - `error`：提示"守护检查暂时开小差了"（[policy.ts:35](../src/lib/server/guard/policy.ts#L35)）。
   - `homework`：
     1. 用"引导模式 + 纠正提示"（[policy.ts:24](../src/lib/server/guard/policy.ts#L24)）让主模型重新生成（[第 130 行](../src/app/api/chat/route.ts#L130)）。
     2. 对重新生成的结果**再审一次**（[第 131 行](../src/app/api/chat/route.ts#L131)）。
     3. 通过就下发，路径 `rewrite`；不通过就用固定引导话术（[policy.ts:31-32](../src/lib/server/guard/policy.ts#L31-L32)），路径 `fallback`。

## 8. 前端接收与展示

SSE 事件在 [useChat.ts:46-55](../src/lib/useChat.ts#L46-L55) 中处理：

| 事件 | 数据 | 前端动作 | 展示（[Message.tsx](../src/components/Message.tsx)） |
|---|---|---|---|
| `reviewing` | `{}` | 状态改为 `reviewing` | 三个点 + 盾牌图标"守护检查中"（[第 157 行](../src/components/Message.tsx#L157)） |
| `drawing` | `{stage, ahead?}` | 状态改为 `drawing`，记录阶段 | 画布占位动效，显示阶段文字和计秒（[第 25 行](../src/components/Message.tsx#L25)、[第 132 行](../src/components/Message.tsx#L132)） |
| `answer` | `{text, image?, guided?}` | 写入内容和图片；`guided` 标为引导 | 打字机效果，最多约 0.9 秒；有图片时显示图片和"保存图片"按钮（[第 141 行](../src/components/Message.tsx#L141)、[第 166 行](../src/components/Message.tsx#L166)） |
| `error` | `{message}` | 状态改为 `error` | 虚线气泡，可以重新回答 |

- 流结束时，如果消息还停在等待状态（连接意外断开），标记为"回答中断了"（[useChat.ts:58-60](../src/lib/useChat.ts#L58-L60)）。
- 页面刷新时，所有还没完成的消息都会改成"被打断"（[sessions.ts:72-75](../src/store/sessions.ts#L72-L75)），未经审查的状态不会残留。

## 9. 审计记录（贯穿全程）

实现在 [audit.ts:18-44](../src/lib/server/audit.ts#L18-L44)。

- **开始**：[route.ts:63](../src/app/api/chat/route.ts#L63) 创建记录，写入角色、对话模型、审查模型、输入字数，以及是否命中引导模式。
- **计时**（[audit.ts:27-30](../src/lib/server/audit.ts#L27-L30)）：
  - `audit.time(阶段, Promise)` 从调用的那一刻开始计时，到 Promise 成功结束为止。
  - 意图审查和生成是并行的，各自独立计时。
  - **只有成功完成的阶段才会记录**，被意图审查中止的那次生成不会计入。
  - 涉及的位置：
    - [route.ts:89](../src/app/api/chat/route.ts#L89)：生成
    - [route.ts:93](../src/app/api/chat/route.ts#L93)：意图审查
    - [route.ts:112](../src/app/api/chat/route.ts#L112)：输出审查
    - [route.ts:130-131](../src/app/api/chat/route.ts#L130-L131)：重新生成与二次审查
    - [index.ts:49](../src/lib/server/draw/index.ts#L49)、[index.ts:53](../src/lib/server/draw/index.ts#L53)：画画提示词的改写与复核
    - [index.ts:63](../src/lib/server/draw/index.ts#L63)：ComfyUI 的排队、渲染、下载
- **补充字段**：意图、审查结论、输出字数、画画模板等，通过 `audit.set` 写入（[audit.ts:31](../src/lib/server/audit.ts#L31)）。
- **结束**：[route.ts:144](../src/app/api/chat/route.ts#L144) 在 `finally` 中调用 `finish`，不管走哪条路径都只写一次；孩子中止时路径记为 `aborted`。
  - `finish`（[audit.ts:34-42](../src/lib/server/audit.ts#L34-L42)）把记录打印成 `[audit] {...}`，同时追加到 `data/logs/audit-YYYY-MM.jsonl`。写入失败只打日志，不影响对话。
- **不记录**对话原文和图片内容。
- 控制台"审计"页读取这些文件，统计 P50 和 P95（[audit/route.ts:43](../src/app/api/admin/audit/route.ts#L43)）；也可以一键清除，清除需要二次确认，删除后不可恢复（[audit/route.ts:36](../src/app/api/admin/audit/route.ts#L36)）。

## 10. 停止、超时与异常

| 情况 | 处理 |
|---|---|
| 孩子点"停止" | 前端中止请求（[useChat.ts:85-90](../src/lib/useChat.ts#L85-L90)）。服务端的 `req.signal` 随之中止，并传到所有模型调用和 ComfyUI 轮询；ComfyUI 任务会被删除或中断。审计路径为 `aborted` |
| 意图审查超时（6 秒） | 当作 `normal`，继续走输出审查 |
| 输出审查超时（6 秒） | 严格模式下返回 `error`，不放行 |
| 画画超时（默认 180 秒，可在控制台修改） | 取消 ComfyUI 任务，回"这次没画出来"，路径 `draw_failed` |
| 主模型报错或返回空内容 | 回"我刚刚走神了"（[route.ts:135-140](../src/app/api/chat/route.ts#L135-L140)），路径 `error` |

## 附：一次请求会调用几次模型

| 路径 | 审查模型 | 主模型 | ComfyUI |
|---|---|---|---|
| 注入拦截 | 0 | 0 | 0 |
| 绕过拒绝 / 不安全提问 | 1（意图） | 1（被中止） | 0 |
| 正常回答 | 2（意图、输出） | 1 | 0 |
| 代写后重写 | 3（意图、输出、二次） | 2 | 0 |
| 画画 | 3（意图、改写提示词、复核） | 1（被中止） | 1 个任务 |

审查模型每次只输出一个单词（改写提示词这一步除外），所以务必选用快速、非推理的模型，并按需通过 `GUARD_EXTRA_BODY` 关闭思考。
