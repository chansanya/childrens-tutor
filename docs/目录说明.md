# 目录说明

按目录说明每个文件的作用。一次对话怎样经过引导和审查，见 [对话流程.md](对话流程.md)；第三方怎样调用接口，见 [第三方接入.md](第三方接入.md)。

```
ChildrensTutor/
├── config/            角色定义与控制台保存的配置
├── deploy/            Docker 部署文件
├── docs/              项目文档
├── examples/          第三方接入示例
├── scripts/           本地打包、发布与接口测试脚本
├── src/
│   ├── app/           页面与接口（Next.js App Router）
│   ├── components/    界面组件
│   ├── lib/           前后端共用代码；server/ 下只在服务端运行
│   └── store/         前端会话存储
└── 根目录配置文件
```

## 根目录

| 文件 | 作用 |
|---|---|
| [README.md](../README.md) | 项目介绍、配置、控制台、绘画、审计、部署说明 |
| [.env.example](../.env.example) | 环境变量模板。复制为 `.env` 后填写；模型和绘画配置也可以留空，到控制台里配 |
| [package.json](../package.json) | 依赖与脚本：`dev`、`build`、`start`、`lint`、`deploy` |
| [next.config.ts](../next.config.ts) | Next.js 配置。设置 `BUILD_STANDALONE` 时输出 standalone 产物到 `.next-release`，供部署使用 |
| [tsconfig.json](../tsconfig.json) | TypeScript 配置，`@/` 指向 `src/` |
| [eslint.config.mjs](../eslint.config.mjs) | ESLint 配置 |
| [postcss.config.mjs](../postcss.config.mjs) | Tailwind CSS v4 的 PostCSS 插件 |
| `.gitignore` | 忽略依赖、构建产物、`.env`、`config/settings.json`（含 Key）、`data/`、`release/` |

## config/

| 文件 | 作用 |
|---|---|
| [roles.json](../config/roles.json) | 默认角色：名称、简介、图标、主题色、问候语、人设，可选专属模型 |
| `settings.json` | 控制台保存的覆盖配置，含模型连接与 Key。自动生成，**不提交** |

部署到服务器后，配置目录改为数据卷 `data/config/`（由 `CONFIG_DIR` 指定）。

## deploy/

| 文件 | 作用 |
|---|---|
| [Dockerfile](../deploy/Dockerfile) | 基于 `node:20-alpine` 的运行时镜像，直接运行本地构建好的 standalone 产物，服务器上不执行 `npm install` |
| [docker-compose.yml](../deploy/docker-compose.yml) | 容器 `childrens-tutor`：端口映射、读取 `.env`、挂载 `./data:/data`、自动重启 |
| [remote.sh](../deploy/remote.sh) | 在服务器上执行：解压发布包 → 初始化数据目录与 `.env` → `docker compose up --build` → 健康检查 |

## scripts/

| 文件 | 作用 |
|---|---|
| [deploy.ps1](../scripts/deploy.ps1) | 本地打包为 `release/childrens-tutor.tgz`，打包时剔除 `.env` 和配置文件；传 `-Server` 时通过 scp/ssh 直接发布 |
| [api-test.cmd](../scripts/api-test.cmd) | Windows cmd 下测试第三方接口 `/v1/responses`：先把中文问题写成 UTF-8 文件再发送，避免乱码；加 `draw` 参数测试画画 |

## examples/

| 文件 | 作用 |
|---|---|
| [node-client.mjs](../examples/node-client.mjs) | 第三方 Node.js 接入示例（OpenAI SDK）：非流式与流式调用、各类异常处理、metadata 处理（含下载图片）；`--test` 一次跑完所有用例并核对 metadata |

## src/lib/server/ —— 服务端核心

只在服务端运行（文件开头有 `import 'server-only'`）。

| 文件 | 作用 |
|---|---|
| [chat.ts](../src/lib/server/chat.ts) | **对话主链路 `runChat`**：注入拦截 → 意图审查与生成并行 → 画画或输出审查 → 审计；网页和第三方共用 |
| [config.ts](../src/lib/server/config.ts) | 配置中心：合并 `settings.json`、`.env` 和内置默认值，提供对话模型、审查模型、硬规则、角色、绘画配置（含出图方式）和 API Key |
| [apikeys.ts](../src/lib/server/apikeys.ts) | 第三方 API Key：生成（明文只返回一次）、只存哈希、定时比较校验 |
| [log.ts](../src/lib/server/log.ts) | 服务日志：按级别输出单行中文文本，同一请求的每行带相同的请求编号；级别可在控制台在线调整 |
| [llm.ts](../src/lib/server/llm.ts) | 大模型统一调用层，支持 OpenAI Responses 与 Anthropic 两种协议；列出模型 |
| [admin.ts](../src/lib/server/admin.ts) | 控制台提交内容的校验；Key 与协议、地址绑定（含云端文生图） |
| [audit.ts](../src/lib/server/audit.ts) | 审计记录：各阶段计时，结束时写一行 JSON 到日志和 `data/logs/` |

### guard/ —— 引导与审查

| 文件 | 作用 |
|---|---|
| [rules.ts](../src/lib/server/guard/rules.ts) | 默认守护硬规则，含常见绕法和示范对话 |
| [policy.ts](../src/lib/server/guard/policy.ts) | 分层引导：系统提示词拼装、引导模式、守则提醒、纠正提示，以及各种固定话术 |
| [intent.ts](../src/lib/server/guard/intent.ts) | 输入侧：注入与作业关键词、意图审查（normal、bypass、unsafe、draw） |
| [review.ts](../src/lib/server/guard/review.ts) | 输出侧：判断回答能否给孩子看（pass、homework、unsafe），支持严格模式 |
| [judge.ts](../src/lib/server/guard/judge.ts) | 审查模型的统一调用：只输出一个单词、6 秒超时、按优先级解析 |

### draw/ —— 画画

| 文件 | 作用 |
|---|---|
| [index.ts](../src/lib/server/draw/index.ts) | 画画流程编排：繁忙检查 → 改写提示词 → 安全复核 → 出图（ComfyUI 或云端二选一） → 下发图片 |
| [prompt.ts](../src/lib/server/draw/prompt.ts) | 用审查模型改写绘画提示词并复核安全性 |
| [comfy.ts](../src/lib/server/draw/comfy.ts) | ComfyUI 客户端：提交、轮询进度、取消任务、下载图片 |
| [api.ts](../src/lib/server/draw/api.ts) | 云端文生图客户端：OpenAI 兼容 `/images/generations` 与百炼原生两种协议，并发计数、厂商审核拦截识别 |
| [image.ts](../src/lib/server/draw/image.ts) | 图片存储：按文件头识别 png/jpg/webp，以随机文件名存入 `data/images/` |
| [workflow.ts](../src/lib/server/draw/workflow.ts) | 内置绘画模板：Z-Image Turbo（默认）、H3 高清 |
